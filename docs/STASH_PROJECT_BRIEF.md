# Stash — Project Brief & Rules

> الملف ده هو المرجع الأساسي للمشروع. لو بدأت محادثة جديدة مع Claude (أو أي AI)، ابعتله الملف ده الأول عشان يلتزم بكل القرارات والقواعد.

---

## 1) فكرة التطبيق

**الاسم:** Stash (مؤكد)
**المنصة:** Flutter (Android / iOS، ومستقبلاً Tablet / Desktop)
**الهدف:** مكان شخصي واحد أحتفظ فيه بحاجاتي المهمة، منظمة في كاتيجوريز، بشكل حلو وسريع.

### المشكلة الأساسية
بلاقي فيديوهات وبوستات مهمة على السوشيال ميديا، فبباخد اللينك وأبعته لنفسي. في الآخر اللينكات بتبقى كتير ومبرجعش لها تاني.

### الحل
- مكان واحد أحفظ فيه اللينكات المهمة.
- اللينك لما أحطه يظهر **كارت فيه صورة الفيديو/البوست + العنوان + المصدر** عشان أعرف ده إيه من غير ما أفتحه.
- **Share Intent:** أدوس "مشاركة" من تيك توك / إنستجرام / يوتيوب / فيسبوك وأختار Stash مباشرة، من غير ما أبعت لنفسي.

---

## 2) الأقسام والمميزات

### أ) اللينكات (Links) — الميزة الأهم
- حفظ لينك (لصق يدوي أو Share Intent).
- جلب تلقائي: `og:image`, `og:title`, `og:description`, اسم الموقع/المنصة.
- حفظ صورة الـ preview **محلياً** (thumbnail مصغرة) عشان تشتغل أوفلاين.
- أيقونة/Badge للمنصة (YouTube, TikTok, Instagram, Facebook, X ...).
- تصنيف في كاتيجوري + Tags + ملاحظة شخصية.
- حالة: "لسه مشوفتوش" / "اتشاف" + مفضلة (Favorite) + أرشيف.
- فتح اللينك في التطبيق الأصلي أو المتصفح.

### ب) المستندات (Documents)
- صور بطاقة شخصية، رخصة، باسبور، ورق مهم، فيز.
- ملفات PDF وصور.
- مسح بالكاميرا (اختياري لاحقاً) + عرض مكبّر + مشاركة.
- تواريخ انتهاء (رخصة/باسبور) مع تنبيه قبل الانتهاء (اختياري لاحقاً).

### ج) عام
- كاتيجوريز كتير ومخصصة (اسم + لون + إيموجي/أيقونة).
- بحث سريع في كل حاجة (FTS5).
- إعدادات: قفل بالبصمة، ثيم (فاتح/داكن)، Backup/Restore، اللغة.

## 3) القرارات المتفق عليها

| البند | القرار |
|---|---|
| الاسم | **Stash** |
| State management | **Riverpod** |
| Navigation | **go_router** |
| الأركتكشر | **Feature-first + Clean Architecture مبسطة** |
| الملفات | تتخزن في فولدر التطبيق (`path_provider`) والداتابيز فيها **المسار بس** |
| الأمان | `local_auth` (بصمة) + `flutter_secure_storage` + تشفير الملفات الحساسة |
| Link preview | OG metadata (`metadata_fetch` أو `any_link_preview`) + كاش محلي للصور |
| Share Intent | `receive_sharing_intent` (أو بديل محدّث) |
| Responsive | مطلوب |
| Performance | High performance مطلوب |

### قرارات لسه مفتوحة (لازم تتحسم)
- [ ] **الداتابيز:** Drift (مرشح) ولا SQFlite
- [ ] **اللغة:** عربي RTL / إنجليزي / الاتنين
- [ ] **الديزاين:** Claude هيعمل 3 اتجاهات مرئية (موك أب) وأنا أختار

## 4) هيكل الفولدرات

```
lib/
├─ core/            ← theme, router, utils, widgets مشتركة, security
├─ data/            ← database, repositories, services (link preview, files)
├─ features/
│  ├─ home/
│  ├─ categories/
│  ├─ links/        ← حفظ + preview + share intent
│  ├─ documents/    ← بطاقة، رخصة، PDF
│  ├─ search/
│  └─ settings/     ← قفل، ثيم، backup
└─ main.dart
```

كل feature جواه:
- `presentation/` → شاشات + widgets + providers
- `domain/` → models + repository interfaces
- `data/` → التنفيذ (DAOs, API, mappers)

---

## 5) قواعد الأركتكشر والكود (Rules)

1. **ممنوع كتابة أي كود قبل ما الديزاين يتختار ويتأكد.**
2. الـ UI ماتكلمش الداتابيز مباشرة؛ دايماً عن طريق Repository + Provider.
3. كل feature مستقل، وماينفعش feature يستورد من feature تاني (المشترك يروح `core/`).
4. الـ Models immutable (`freezed` أو ما يعادله) + `json_serializable` عند الحاجة.
5. الـ Theme كله مركزي في `core/theme` (ألوان، خطوط، spacing، radius، ظلال) كـ tokens؛ **ممنوع** hard-code لألوان أو أحجام جوه الـ widgets.
6. كل النصوص في ملفات localization، مفيش string مكتوب جوه الكود.
7. معالجة الأخطاء صريحة (loading / empty / error states لكل شاشة، وتكون متصممة حلو مش نص افتراضي).
8. كود نضيف، أسماء واضحة، ملفات صغيرة، والشرح بالعربي في الرد والتعليقات القصيرة بالإنجليزي في الكود.
9. أي package جديد يتذكر سببه، ويفضّل الموثوق والمتحدّث.
10. كتابة الكود على مراحل: Data layer ← Theme ← الشاشات شاشة شاشة، وكل مرحلة تتراجع قبل اللي بعدها.

## 6) قواعد الـ Performance

- `ListView.builder` / Slivers دايماً، مفيش قوائم كاملة مرة واحدة.
- Thumbnails مصغرة في الكروت، ماتحملش الصورة الكاملة.
- كاش للصور (`cached_network_image` أو كاش مخصص) + حفظ محلي.
- البحث بـ **FTS5** بدل `LIKE`.
- جلب الـ metadata وعمليات الملفات الثقيلة في **Isolate** أو background.
- `const` widgets قدر الإمكان، و`select` في Riverpod لتقليل الـ rebuilds.
- Pagination للقوائم الكبيرة.
- Indexes على الأعمدة المستخدمة في الفلترة (category, createdAt, ...).
- مفيش `setState` ثقيل ولا rebuild لشجرة كبيرة.
- الأنيميشن خفيفة وبـ 60/120fps، وماتتعملش على حساب الأداء.

---

## 7) قواعد الـ Responsive

- `LayoutBuilder` + breakpoints: **Mobile** (<600) / **Tablet** (600–1024) / **Desktop** (>1024).
- Grid عدد أعمدته بيتغير حسب العرض (`SliverGridDelegateWithMaxCrossAxisExtent`).
- Tablet: Navigation Rail بدل Bottom Bar + شاشة Master-Detail.
- دعم Portrait و Landscape.
- مراعاة Safe Area والـ keyboard والنصوص الكبيرة (Accessibility).

---

## 8) قواعد الأمان والخصوصية

- المستندات الحساسة (بطاقة/رخصة/باسبور) **متشفرة** على الجهاز.
- مفتاح التشفير في `flutter_secure_storage`.
- قفل التطبيق بالبصمة/PIN (اختياري لكل التطبيق أو لقسم المستندات بس).
- منع Screenshot / إخفاء المحتوى في الـ recent apps للأقسام الحساسة (اختياري).
- مفيش رفع بيانات لأي سيرفر؛ كله محلي (Local-first). أي Backup يكون مشفّر.

## 9) قواعد الديزاين (الأهم)

> **الهدف:** تطبيق له هوية وشخصية، مش شكل AI عام ولا Material افتراضي.

### ممنوع
- ❌ **اللون الأزرق** كلون أساسي (ولا درجاته الافتراضية).
- ❌ Material Icons الافتراضية.
- ❌ الشكل الافتراضي (AppBar أزرق، FAB دايرة زرقا، كروت رمادي باهت).
- ❌ Gradients بنفسجي/أزرق المعتادة.
- ❌ تكرار نفس الديزاين من مشروع لمشروع.

### مطلوب
- ✅ هوية بصرية واضحة: palette محدد (3–5 ألوان) + لون accent قوي.
- ✅ خط مميز (عنوان + نص) يدعم العربي لو اللغة عربي (مثال: Cairo / IBM Plex Sans Arabic / Readex Pro).
- ✅ أيقونات مميزة (`phosphor_flutter` أو `iconsax` أو إيموجي كبيرة للكاتيجوريز) بدل Material.
- ✅ Spacing منتظم (مقياس 4/8)، وradius ثابت ومدروس، وظلال ناعمة أو حدود حسب الاتجاه.
- ✅ كروت اللينكات تعرض الـ thumbnail بشكل جذاب (نسبة أبعاد ثابتة، Skeleton أثناء التحميل).
- ✅ Empty states ظريفة ومصممة، مع Illustration أو إيموجي.
- ✅ Micro-interactions خفيفة (haptics، transitions ناعمة، Hero للصور).
- ✅ Dark mode متصمم بعناية، مش مجرد عكس ألوان.
- ✅ Contrast كويس وقابلية قراءة عالية.

### اتجاهات الديزاين المقترحة (للاختيار بينها)
1. **Warm minimal** — كريمي + تيراكوتا/زيتوني، حواف دائرية كبيرة، إحساس دافي وهادي.
2. **Bold & playful / Neo-brutalism** — ألوان جريئة (أصفر ليموني + أسود)، حدود سميكة، ظلال صلبة.
3. **Dark luxe** — خلفية داكنة، أخضر/ذهبي هادي، إحساس خزنة أنيقة.

(الاتجاه النهائي: **لسه هيتحدد** بعد ما أشوف الموك أب.)

## 11) تعليمات لأي AI يقرأ الملف ده

- التزم بكل القواعد فوق حرفياً، وماتغيّرش قرار متفق عليه من غير ما تسأل.
- ماتكتبش كود قبل موافقتي على الديزاين.
